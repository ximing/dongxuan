# 本地运行与快照迁移

真实应用使用 React、Fastify、PostgreSQL；`docs/design` 继续保留设计参考。生产业务不读取设计稿 fixtures 或电脑上的技能目录。

## 隔离开发环境

不要将日常开发或集成测试指向现有远程数据库。以下脚本显式覆盖数据库、端口、cookie/JWT 与 OIDC 环境变量，使用独立本地容器和数据库：

```bash
pnpm install
pnpm --filter @dongxuan/dto build
pnpm dev:local:db
pnpm dev:local:server
```

在另一终端启动前端：

```bash
DONGXUAN_API_TARGET=http://127.0.0.1:3041 pnpm --filter @dongxuan/web dev
```

前台启动的开发服务由终端持有，使用 Ctrl-C 停止。若需要在自动化任务结束后继续预览，可运行 `node apps/server/scripts/local-env.mjs background`，它以独立后台进程启动、把 PID 与日志保存在忽略提交的 `apps/server/.runtime.local/`。检查 `/health` 成功后再操作页面；停止后台服务用 `node apps/server/scripts/local-env.mjs stop`，脚本先核对 PID 属于本项目再发送信号。

前端地址以 Vite 输出为准（当前默认 `http://localhost:5192`）；API 在 `http://127.0.0.1:3041`。本地 OIDC 被关闭，可在真实登录页注册自己的测试账号。此账号只存在本地容器，生产登录逻辑保持原有认证要求；没有开发绕过接口。

`compose.local.yml` 暴露端口仅绑定 `127.0.0.1:55439`，数据保存在 Docker named volume。停止容器用 `docker compose -f compose.local.yml stop`；不要在需要保留测试资料时删除 volume。

## 验证

```bash
pnpm typecheck
pnpm build
pnpm test
pnpm test:local
```

`pnpm test` 跑纯单元/计算测试；API 集成测试默认跳过。`pnpm test:local` 只对显式隔离的 `localhost:55439` 运行，创建独立 `dongxuan_test` 数据库并在结束后清理本次账号资料。它验证真实 PostgreSQL 迁移、鉴权隔离、幂等与修订冲突、单次快照写入、不可变读取、视图预览绑定、笔记引用保护、模板机制、多年月资料、梅花原始输入与 legacy 回填。

## 生产迁移顺序

1. 安排维护窗口并停止全部旧服务实例。备份现有库与部署版本，先在备份副本演练迁移与恢复。例：`pg_dump -Fc -f backup-before-v2.dump <连接参数>`；将备份恢复到独立库，核对用户与命盘数量。
2. 配置正确的目标数据库，再运行 server `migrate`。`schema_migrations` 记录已应用版本，事务与 advisory lock 避免并行执行；第二次运行不会重复建表或改列。
3. 新结构保留全部旧输入列和命盘 ID；迁移增加数据库命盘写屏障，旧版进程无法继续只写输入。新服务在事务中标识 v2 writer，同时写旧列与不可变基础快照。
4. 运行 `pnpm --filter @dongxuan/server exec tsx src/v2/backfill.ts`。回填从仓库内冻结的旧实现计算，以基础快照唯一索引保证幂等；失败保留输入并标记待修复。来源明确为“迁移时按既有逻辑重建，并非创建当日历史结果”。
5. 核对回填返回的 `total / ready / failed`，并查询每张 ready 命盘恰好一份基础快照。列表/详情读取存储结果；读取失败记录不会偷偷生成空盘。启动新服务也会执行幂等迁移与回填。CLI 回填 `failed > 0` 时以非零状态退出；新服务存在失败时拒绝开放 HTTP，需保持维护窗口、依据失败记录修复输入并重新回填，直到数量核对通过。
6. 用旧 URL、列表摘要、文字盘和跨账号隔离作抽查；恢复访问。旧引擎快照继续可读，若需要新运限，应另起当前规则盘。

旧版服务不理解新快照、笔记和模板。切换后已有新数据时，不能简单启动旧二进制回滚；应回滚到兼容快照的版本，或在维护窗口恢复完整备份。首次迁移保留旧列，不执行破坏性清理。

## 当前能力边界

紫微正式计算支持经过校验的日期范围、当前/下一大限、完整多流年与连续 1–12 阳历月。月份按实际叠盘身份分段。规则固定为普通年界/月份、晚子归次日；节气四柱按时辰代表时刻取样。

梅花在统一 header 有独立入口，原始问题、两个整数及可选命盘真实持久化。起卦规则尚待确认，结果模板明确提示缺卦象，原始请求模板可以复制；八字与奇门计算仍规划中。站内不执行外部 Agent 提示词。

已保存视图用于提示词时绑定其精确查询和版本，同范围使用原始结果；参数不一致会阻断，界面可明确清除视图绑定、改从基础盘取数。仅需要当前大限时不要求下一大限可得；明确需要当前/下一组合时仍要求两者完整。年份和查询整段越界会明确报错，不静默截短。

本地及自动化验证完成不表示已经发布生产。默认固定分界规则、已验证的 1901–2099 日期范围与虚岁不超过 120 岁仍是当前计算能力边界；跨到边界之外的整个年度/月窗口会拒绝。多流年逐日完整核对可能需要数秒，界面会显示等待状态。

## 列表分页

命盘、笔记、模板、梅花草稿和已保存运限列表支持 `?limit=1..100&cursor=...`，返回 `{items, nextCursor, hasMore}`。默认每页 50；游标不可伪造，并绑定账号、列表和筛选条件，变更筛选必须从第一页重新读取。排序以创建时间和唯一 ID 为依据，保留数据库微秒精度，续页不会因为同毫秒记录而漏项。

命盘支持服务端 `search`（称呼或关系）和 `archived=true|false`。笔记按 `chartId` 或 `snapshotId` 筛选，梅花草稿按 `chartId` 筛选，模板按术数和标题筛选。主列表使用“加载更多”；表单来源选择逐页读取到结束。兼容旧客户端的无分页参数请求仍返回完整数组，没有 500 条截断。静态术数/变量目录只有固定枚举，回填命令返回全库聚合计数，不使用用户列表分页。
