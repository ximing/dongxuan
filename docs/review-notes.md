# Review 与定位修正记录

日期：2026-11-23。

## 最新产品修正

用户明确：东玄是给自己用，也会帮别人看盘，因此需要档案；不是职业命理师，不需要工作台。首页直接排盘，旁边选已有档案。

据此撤销此前客户、咨询案例、回访状态和职业工作台设计，改为人物档案、命盘与简单笔记。笔记可直接编辑，不保留此前专业案例所需的不可变修订链。产品、架构、路线图和 HTML 设计稿同步更新。

2026-11-24：人物档案不再单独存在，并入命盘。一张命盘就是一个人。未关联人物筛选随之取消。

## 此前 SubAgent Review 中继续适用的结论

三个 SubAgent 曾分别 review 产品、紫微规则和架构，修订后复审通过。该结论针对当时文档，不代表本次个人定位已经再次经过 SubAgent review；以下技术结论仍然适用：

| 问题 | 当前方案处理 |
| --- | --- |
| normal 闰月十六发生流月变化，脚本可能漏分段 | 根据实际运限身份分段，独立保存农历标签 |
| 童限被脚本写成“大限 85–94 虚岁” | 尊重库返回类型，不套本命大限区间 |
| 查询出生前/超范围仍可能返回貌似有效结果 | 独立业务区间校验，越界不生成盘 |
| 输入 HH:mm 容易被理解成精确节气计算 | 明确输入精度与技能时辰取样精度不同 |
| 无效闰月被库降级为普通月 | 在排盘校正前做纯历法往返核对 |
| 全量 chart/kind 唯一限制多个运限快照 | 仅基础快照条件唯一 |
| 修改 renderer 后再迁移无法保存旧格式 | 修改前冻结 legacy 重建入口 |
| 回填期间旧服务新写入可能遗漏 | 维护窗口写屏障；不停机则先原子双写 |
| 旧出生列 NOT NULL 与新存储冲突 | 过渡期同事务兼容写入 |
| 预览和保存之间换版导致结果不同 | 凭证绑定完整计算身份与结果指纹 |
| 独立盘无查找入口 | 全部命盘可查找。2026-11-24 起不再有未关联人物筛选 |
| 表单示例默认值伪装成已知资料 | 初始生日、时辰、性别为空 |

案例摘要、跟进状态等原 review 的产品补充已随职业场景撤销，不再作为实施任务。

## 证据与边界

计算发现来自锁定 iztro 2.6.5、指定技能脚本及合成样例；闰月与童限结果由主 Agent 复现。普通月份范围也经逐日核对。详见 [紫微规则](ziwei-rules.md)。

迁移发现来自当前 schema 的 NOT NULL 出生列和仅保存输入的创建路径。没有连接生产数据库或处理真实个人数据。

文档修正不等于业务修复完成。完整计算样例、迁移恢复和真实浏览器流程仍需在实现时验收。
