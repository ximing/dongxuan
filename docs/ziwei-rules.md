## 2. 规则对照

| 项目 | 技能/脚本实际约定 | 站点设计 |
| --- | --- | --- |
| 出生日期 | 阳历或农历，闰月需明确 | 保存原始历法和输入，不只保存转换后的阳历 |
| 时间 | 钟点或时辰；0 早子，12 晚子；“子时”须澄清 | 支持钟点与时辰两种输入，保存输入精度和原值 |
| 性别 | 排盘所需男/女 | 明确用于排盘的字段，不从称呼或其他资料推断 |
| 默认分界 | 默认年界为春节；普通农历月初一换流月；库在闰月十六日另有流月推进 | 首版开放 `normal`，按库返回的实际运限状态分段，不把“初一换月”当成完整算法 |
| 可选分界 | `--divide exact` 设置 `yearDivide`、`horoscopeDivide` | 模型预留，首版暂不开放，见第 5 节 |
| 晚子 | 脚本未覆盖库默认；2.6.5 默认 `dayDivide: forward` | 建议显式晚子归次日，修正文案；不改成当日规则 |
| 闰月处理 | `fixLeap = true`，闰月输入另由 `isLeapMonth` 指定 | 与参考一致，并把两项纳入规则/输入快照 |
| 年龄 | 库区分童限/大限；脚本部分文字未正确区分 | 清楚标“虚岁”，按库类型显示童限/大限；不得把童限落宫的本命大限区间当成当前年龄段 |
| 四柱 | 库内四柱和技能口径的节气四柱同时输出；后者按时辰代表时刻取样 | 分别存储、分别标注，不用节气四柱替换紫微安星结果，不宣称分钟级节气精度 |
| 文字顺序 | 寅、卯、辰、巳、午、未、申、酉、戌、亥、子、丑 | 新文字盘遵循参考；图形盘保留空间布局 |
| 运限目标日 | `astrolabe.horoscope(iso, 0)` | 明确“指定日视图”，目标时辰固定早子，不声称支持流时 |

规则配置必须是每次计算的显式输入，并与结果一起保存。不能随着账号偏好变化回写旧盘。官方文档也列明了年界、运限分界、虚岁分界、晚子归属和安星方法等配置项，且晚子默认归次日。[iztro 配置文档](https://iztro.com/posts/config-n-plugin)

时间范围使用半开区间：早子 `[00:00, 01:00)`、丑 `[01:00, 03:00)`，依次类推，晚子 `[23:00, 24:00)`。脚本接受 `24:00` 并映射早子，但没有同时推进输入日期；站点首版应拒绝 `24:00`，提示填写次日 `00:00`，不能照搬这个模糊行为。

当前时间语义限定为用户确认的排盘用民用日期和钟点；不做自动时区、夏令时或真太阳时校正。只知道时辰时，不伪造精确分钟。

即使用户填写 `HH:mm`，参考脚本也先映射为 `timeIndex`；其 `lunar-lite` 路径按时辰代表时刻取样，寅时例如取 `03:30`。节气四柱的年柱与月柱还分别使用立春日期、节气时刻口径，因此不能笼统称为“按用户出生分钟精确计算”。首版展示“节气四柱（技能时辰取样）”，计算依据记录取样口径；精确钟点只作为原始资料保存。将来支持精确交节计算须成为独立规则版本，不静默替换现有结果。

农历校验不能只依赖 iztro 是否抛错：已复现 `byLunar('2024-2-1', 6, '男', true, true, 'zh-CN')` 被降级成普通二月初一。站点须独立校验当年闰月是否存在、闰月月份及日期是否合法，在纯历法转换阶段反向核对原始年月日和闰月标记；不匹配直接拒绝，不自动改成普通月。该核对先于晚子换日和排盘闰月校正，不能拿推进后的 `astrolabe.lunarDate` 与原输入比较。

## 3. 技能能力如何进入站点

### 3.1 本命盘

保留现有十二宫图形盘，补齐技能文字输出中的资料和解释：阳历、农历、两套四柱、性别、生肖、星座、五行局、时辰、命主身主、命宫身宫、主星辅星杂曜、神煞、大限虚岁区间、生年四化。

文字盘采用参考脚本已验证场景的格式作为基准正文。站点上的称呼可以放在正文外层，不能凭经验改写星名、亮度、四化、宫位或日期范围。第 5 节已确认的脚本缺陷须按库结果修正，记录格式/适配器版本，作为明确的基准例外。新导出附上计算依据；旧文本快照保留原貌。

技能 `natalText`、`palaceBlock`、`mutagenLine` 对应新的紫微格式化模块；`renderChart` 中的计算、字段投影和文本拼接拆开，供图形盘与文字盘共用一个结果。

### 3.2 指定日视图

输入一个阳历日期，显示该日的大限、流年、小限、流月、虚岁及四化，宫位叠加显示本命与各运限宫名。选择“含流日”才追加流日。

尚未进入首个大限时显示库返回的“童限”，不硬写“大限”，也不展示该落宫本命的大限年龄区间。目标日在出生之前时不提供个人运限查询；出生当天晚子导致计算日跨日的情况作为独立边界样例验证，不能把合理输入误判为出生前。

查询范围校验先于输出：出生前日期、超出已验证支持区间，或引擎返回负数/越界宫位索引、缺失运限结构，均返回明确的不可查询错误，不生成快照。首版月窗口只要含不可查询日期就整请求拒绝，返回问题日期段，提示缩小月份或改查指定日；不静默裁剪成看似完整的月份。首发前依据锁定库与样例明确支持的出生日期及目标日期区间，并作为引擎能力公开；不按“四位年份”正则推断支持全部年份。

流曜在结构化结果中保留来源层级，不能把本命与大限、流年、流月流曜混成一组后失去依据。图形盘按层开关；参考文字可保持脚本的排版次序。

对应脚本 `horoscopeSection`、`scopeLine`、`overlayBlock`。同一宫位的索引须用库返回的稳定映射处理，避免前端网格顺序与库数组顺序混淆。

### 3.3 阳历月份查询

月份是查询窗口，流月是计算单位。界面需要同时显示：

1. 用户查询的阳历月份。
2. 这个窗口内每段覆盖的起止日期。
3. 依据引擎运限身份确定的流月有效区间；另列农历整月范围，二者不得混用。
4. 该段大限、流年、流月的结果引用；跨窗口重复时显示“同上一流月”，不重复排整盘。

本地合成样例：阳历出生 `2000-08-16`、晚子、男，查询 `2026-11,2026-12`，默认规则输出：

| 查询覆盖 | 完整流月范围 | 展示 |
| --- | --- | --- |
| 2026-11-01～11-08 | 2026-10-10～11-08 | 首次完整展示 |
| 2026-11-09～11-30 | 2026-11-09～12-08 | 首次完整展示 |
| 2026-12-01～12-08 | 2026-11-09～12-08 | 引用上一流月 |
| 2026-12-09～12-31 | 2026-12-09～2027-01-07 | 首次完整展示 |

上述日期取自参考脚本实际输出，不是手工推算。实现基准命令：

```bash
node /Users/ximing/.agents/skills/iztro-chart/scripts/chart.mjs \
  --solar 2000-08-16 --time 23:30 --gender 男 \
  --months 2026-11,2026-12 --on 2026-11-15 --daily
```

对应 `monthSections`、`lunarOf`、`lunarSpan`，但脚本当前分组不足以覆盖所有默认模式场景。站点应逐日比较库返回的实际运限身份，包括童限/大限类型与宫位、流年、小限/虚岁、流月宫位及干支、宫名映射、四化和各层流曜；同一身份的连续日期才可合段。流日只在指定日模式独立处理，不纳入月份合段。查询月份先排序去重，再计算覆盖段与视图引用。

当前脚本的 `lunarSpan` 只能当农历整月范围标签。真实流月边界须向前后查找库返回的流月身份变化点；整套叠盘的有效范围则还受大限/流年等变化约束。按库已验证日期范围限制查找；触及边界而无法求出完整范围时标记“范围未完整”，不能猜结束日期。农历整月标签可在多个段重复，视图去重不能吞掉日期覆盖或闰月标签。

`segments` 也可在农历标签变化时切段，即便相邻段运限身份一致；此时共用一个 `view`，分别保留各段农历标签。尤其闰月后半与下一普通月结果相同时，不能因合并视图而丢掉日历语义。

## 4. 已复现的现有站点问题

### 4.1 晚子文案与计算不一致

站点 DTO 注释、首页提示和 README 写“晚子时按出生当日”，但 `renderChart` 没有配置 `dayDivide`。本地 `astro.getConfig()` 返回 `forward`。

对合成输入 `2000-08-16 / timeIndex=12 / 男`，现有默认结果农历为七月十八，库内四柱为 `庚辰 甲申 丁未 庚子`；显式改为 `current` 后为七月十七，四柱为 `庚辰 甲申 丙午 戊子`。技能脚本与默认结果一致。

建议：新盘显式采用技能当前规则，修正提示。历史盘先按迁移时的现有行为存快照，标记来源；不能批量改成“当日”并覆盖历史记录。这个问题不是只换一句文案就能完成历史说明，迁移要求见架构文档。

### 4.2 农历输入使用阳历控件

`HomePage` 在两种历法下都使用 `<input type="date">`，可能拦截合法农历日期，例如农历某月三十日对应的数字组合不一定是合法公历日期。应为农历使用独立年月日与闰月选择，并由服务端历法验证。

### 4.3 结果没有持久化

目前只存输入，列表遍历所有命盘计算摘要，详情也重新计算。无法保证库升级后与当时所见一致；新增时还会在校验和构建响应阶段各算一次。改为单次计算、落库快照、列表读取摘要。

### 4.4 两套四柱尚未区分

当前文字盘只把 `astrolabe.chineseDate` 标为“四柱”。展示时应明确这是库内四柱，并增加参考脚本的节气四柱与差异说明。两者不是可以互相覆盖的显示别名。

## 5. 参考脚本的适用边界

参考技能确定产品语义和基准结果，但 CLI 实现不应直接搬成长期运行的服务：

- **默认模式闰月分段（已复现）**：出生 `2000-08-16`、晚子、男，查询 `2025-08`，脚本把 `08-01～08-22` 合成一段癸未流月。但 `horoscope('2025-8-8', 0)` 返回闰六月十五、流月 `index=2/癸未`，次日闰六月十六返回 `index=3/甲申`。本命 `fixLeap=true/false` 均可复现，因为目标流月的闰月处理独立于本命闰月参数。分组键缺少实际 monthly 身份，因此 normal 首版也必须先修复；不能仅把缺陷列在 exact 模式。修正来自库返回值，不手排。
- **童限年龄误标（已复现）**：出生 `2025-01-01`、午时、男，目标 `2025-02-01`，库返回 `decadal.name='童限'`、虚岁 2；脚本固定输出“大限”并取该落宫的本命区间，得到 `85–94 虚岁`。站点须保留运限类型，童限不展示这个不适用区间。
- **查询有效性（已复现）**：同一出生 `2025-01-01` 样例查询 `2024-12-30`，库仍返回看似有效的虚岁 1/童限；查询 `2200-01-01` 得到 `decadal.index=-1`。不得只依赖库调用成功或日期格式校验。
- **节气四柱精度（已复现）**：本地锁定依赖的 `2026-02-04` 立春时刻为 `04:02:08`；技能接受 `04:00` 与 `04:10` 后都映射为寅时并输出同一节气月柱，底层精确时刻算法则已跨交节。这是当前参考口径的限制，首版保留并说明，不擅自改用另一套四柱算法。
- **节气模式分段**：`--divide exact` 改了计算分界，但 `monthSections` 分组键仍使用 `lunar.key`，`lunarSpan` 也始终求农历整月。因此不能把当前输出的农历范围当成节气流月有效范围。此结论来自源码审阅；尚未完成节气边界全量验证。首版建议仅开放 `normal`；之后按实际运限切换点重写分段并独立验收。
- **全局状态**：CLI 一次进程只排一个请求，`astro.config()` 可用；服务端交错请求不能依赖可变全局配置。优先核验并使用锁定版本的请求级配置，必要时隔离计算，禁止用“修改全局后等待异步任务”的实现。
- **进程退出**：`fail()` 会退出进程，迁入服务时改成可定位的业务错误；算法错误不能退回一份看似正常的盘。
- **宽容字段投影**：当前站点未知字段可能降级为空星列表或 `0` 索引。关键字段必须校验；缺宫、重复宫位等结构错误应明确失败，不能输出错误空盘。
- **基准与缺陷区分**：默认已支持场景以脚本为基准；发现边界缺陷时建立独立修正样例、记录规则版本，不为追求字节一致而复制错误，也不静默改掉基准。

## 6. 必须建立的验证样例

| 类别 | 覆盖 |
| --- | --- |
| 基础 | 男/女、阳历/农历等价输入、十二宫唯一、身宫与四化 |
| 输入 | 缺日期/性别/时辰、模糊子时、无效日期、不存在的农历闰月及反向核对、农历三十日 |
| 时界 | 00:59/01:00、22:59/23:00、早子/晚子、月末与年末晚子、拒绝 24:00 |
| 年月界 | 春节前后、立春与春节之间、闰月、农历初一前后 |
| 运限 | 指定日含/不含流日、童限及首个大限边界、拒绝出生前及超支持范围目标日、月份部分越界拒绝、跨大限年龄、跨年、阳历跨农历月、相邻查询月去重、闰月十五/十六切换及有效范围 |
| 一致性 | 图形与文字指向相同宫位和四化；两套四柱各自来源及精度正确；节气交接时辰内的取样说明；旧盘读取不重算 |
| 隔离 | 两个规则配置交错调用不污染；其他用户不可读取命盘、笔记与快照 |

实现时保存合成输入、参考脚本版本/哈希、预期结果和预期错误。基准样例验证确定性计算，不证明命理解读的有效性。
