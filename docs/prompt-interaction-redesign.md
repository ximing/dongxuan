# 提示词交互优化：默认使用，需要时编辑

更新：2026-11-24。状态：已按本方案接入实际提示词页面，独立 HTML 演示保留供对照。见[业务实现与验收](prompt-interaction-validation.md)。

[打开交互演示](design/prompt-workbench.html) · [既有需求与资料边界](prompt-templates.md)

## 建议

将提示词页的默认任务改为「用已有模板生成一次提示词」。选择模板后，直接填写这次需要的命盘、时间与问题；模板正文、填写项定义和变量插入放到独立的「编辑模板」模式。桌面将填写与结果并排，减少上下寻找。

常用路径是：选模板 → 填本次资料 → 生成并复制。需要检查全文时先点「查看预览」。首次使用不需要理解变量名，也不需要先保存一次模板。

继续沿用东玄已经确认的白灰底、墨色文字、青绿主操作与系统无衬线字体。变化主要来自信息顺序和操作收敛，便于和命盘页保持一致。

## 改造前的问题

以下记录改造前业务实现中的问题，而非只看旧设计稿：

| 当前行为与位置 | 使用成本 | 优化 |
| --- | --- | --- |
| 页面先渲染模板名称、术数、正文、填写项定义、变量入口和四个编辑操作；本次资料在下面 | 每次使用都要穿过维护模板的界面 | 默认展示本次表单，切换后才展示编辑器 |
| 模板库只有名称与术数 | 要点开、阅读正文才知道用途与必填内容 | 名称下显示一句用途与填写量；支持搜索、常用和术数筛选 |
| 编辑区、资料区和展开结果纵向堆叠 | 填写与校对往返滚动，正文长时尤其明显 | 桌面两栏；窄屏顺排；手机提供填写与结果切换 |
| 生成按钮叫「检查并生成预览」，复制在成功后才可用 | 每次固定需要生成、找结果、再复制 | 主操作为「生成并复制」，次操作保留「查看预览」 |
| 修改调用 invalidate，直接清空 preview | 无法对照上一份结果，也难判断是否需要重来 | 保留上次结果，标记「待更新」，禁止复制旧文本 |
| guard 在有模板修改时阻止切换，提示先保存或撤销 | 不经意碰到正文就被迫处理保存事务 | 编辑草稿按模板分别暂存，切换不阻断；默认使用已保存版 |
| 填写项同时暴露内部 key、名称、类型、必填与移除 | 增加一个问题也像在配置开发参数 | 常规只编辑名称、类型与必填；内部 key 自动生成且稳定 |
| 变量目录平铺多个来源 | 查找困难，需要先了解命名空间 | 「插入资料」按中文名称搜索，保留技术名供核对 |
| 资料错误与诊断通常在生成后集中出现 | 用户缺少“去哪里补”的明确方向 | 先做字段就地校验，服务端诊断再按来源与覆盖范围展示 |

代码依据：

- 页面结构、操作名称与布局： [提示词页面](../apps/web/src/pages/prompts/index.tsx)、[页面样式](../apps/web/src/pages/prompts/styles.css)。
- 草稿判定、切换阻断、资料清空与生成失效： [PromptsService](../apps/web/src/pages/prompts/prompts.service.ts) 中的 dirty、guard、select、selectChart、invalidate、generate。
- 模板、填写项及预览契约： [DTO](../packages/dto/src/v2.ts)。
- 已有模板 CRUD 和预览接口： [API 客户端](../apps/web/src/api/prompts.ts)。

当前实现已经按变量决定显示哪些日期和填写项，也会在换命盘时清空本次输入。这些行为应继续保留。本提案优化组织方式，不把已有能力描述成新增后端能力。

### 使用模板

模板列表提供用途说明。分类优先用术数，不额外引入项目、标签管理、文件夹或多层导航。常用只是一个可切换的收藏标记，不引入排序配置。

选中后先显示模板的中文名称和用途。模板默认不可编辑，用户不容易把某次问题写进公共正文。直接从命盘、保存视图或梅花入口进入时，显式带入该次上下文并显示来源。

关联资料保持一处入口：

- 命盘选择与必要时间范围直接可见。来自命盘页时沿用明确带入的命盘，不要求重新选择；普通入口没有上下文时显示选择器，不猜测身份。
- 自动引用内容以中文标签列出，不要求用户逐项勾选已经写在正文里的变量。
- 基准日默认今天，放在可展开的时间设置里；摘要标出实际基准日。月份与流年范围直接显示，不能藏进高级设置。
- 绑定保存视图时显示「来自保存视图：范围」以及「更换来源」。修改范围会明确解除绑定，不能静默继续显示原快照名称。
- 虚岁、当前大限、流年年界、月份覆盖等取数语义不改变。隐藏复杂度仅发生在默认展示层。

本次填写只展示正文实际引用的项。必填以星号标记，错误显示在字段下面；选填统一说明留空会标为「未提供」。示例按钮仅在原型中帮助体验，正式产品可采用字段级示例占位文案，避免把示例误当用户数据。

### 编辑模板

使用与编辑采用同位置的模式切换，不另开一张需要重选命盘的页面。

左侧是名称、术数与正文；右侧是识别出的关联资料和填写项。添加填写项自动生成稳定 key，中文名称修改不影响正文引用。通过「插入正文」决定填写项位置；未被引用时明确标记，避免用户以为增加定义就会自动出现在结果里。

「插入资料」支持中文名称和内部变量名搜索，插入到正文当前光标处。待接入来源可以用于准备模板，但必须显示状态，并阻止相关模板生成。

草稿与已保存模板分开。切换到其他模板时保留当前模板草稿；回到使用模式显示「有未保存草稿，当前使用已保存版本」。主操作为「保存并使用」，提交成功后返回本次表单。模板保存失败保留草稿，不伪装成已保存。

新增和副本统一使用一个轻量对话框：名称、术数、从空白或当前已保存模板开始。创建后进入编辑状态。「删除模板」建议放在低频管理菜单中，保留二次确认；本次演示没有加入删除入口。

## 关键状态与反馈

| 状态 | 可见反馈 | 操作 |
| --- | --- | --- |
| 尚未生成 | 结果区解释会合并哪些内容 | 可直接生成或先预览 |
| 必填缺失、格式错误 | 字段下说明原因，汇总全部缺项，聚焦首个问题 | 补齐后重试；输入内容保留 |
| 正在计算 | 按钮显示整理/检查状态，结果区有忙碌状态 | 防重复提交；变更输入则旧请求作废 |
| 生成成功 | 全文、来源、范围、字符数显示；复制反馈明确 | 可重复复制 |
| 输入发生变化 | 上次全文保留，标为「待更新」 | 复制禁用，重新生成 |
| 来源能力未接入 | 模板表单顶部说明缺少什么、可改用哪个模板 | 不生成虚构或不完整结果 |
| 自动复制失败 | 提示已生成但未复制，全文完整保留 | 再点复制；仍失败时选择全文手动复制 |
| 模板切换 | 切换表单，清除上次本次输入与结果；保留当前命盘和时间条件 | 防止不同模板字段误串 |
| 命盘切换 | 清空前一个人的本次输入，旧结果标为待更新 | 明确提示已清空，可重新填写 |
| 未保存的编辑 | 模板列表显示草稿标记，当前页面保留草稿 | 可切换、恢复编辑或撤销 |

资料改变时清除旧诊断并标记结果失效；结果文本只作为对照保留，不能再次复制。与异步预览绑定的请求版本必须覆盖模板、来源、时间、输入和保存事件，迟到响应不能覆盖当前状态。

主操作不在实际生成前写入剪贴板。调用现有预览接口成功且没有阻断诊断后才尝试复制；浏览器如果要求重新触发用户手势，保留结果并把复制作为下一步明确展示。不能把「已生成」当成「已复制」。

手机不同时压缩三栏：模板库改成可横向浏览的紧凑列表，搜索继续可用；工作区分「填写资料 / 查看结果」。生成成功自动切到结果，失败留在填写并定位缺项，字段输入保持至少 16px。按钮固定在填写区域底部，键盘和滚动均可抵达。

## 演示范围

[prompt-workbench.html](design/prompt-workbench.html) 是单个文件，无构建、外部字体、图片或 API 依赖，可以直接用浏览器打开。

可试的内容：

1. 默认流月模板直接填写动作，或点「填入示例」，再预览、生成并复制。
2. 空着动作生成，查看必填定位；改月份或正文后查看结果的待更新状态。
3. 切到多年比较模板，所有现实字段留空仍能生成，结果明确保留「未提供」。
4. 换一张示例命盘，本次填写清空，旧结果禁止复制。
5. 切到梅花原始请求，填写问题和两个整数；完整卦例模板会明确阻断。
6. 搜索、筛选、收藏模板；进入编辑后插入资料、添加填写项、切换模板再恢复草稿。
7. 新建、复制、保存模板并刷新；保存后的模板保存在本浏览器。草稿和本次填写刷新不保留。
8. 手机宽度切换填写与结果；使用键盘打开/关闭对话框；使用 Ctrl/⌘ + Enter 生成或保存。

演示内人物和填写示例都是虚构数据。生成结果在开头标为演示文本，命盘、大限、流年和流月位置使用明确占位说明，不包含模拟星曜、假完整性证明或假计算结果。五份模板是为检验交互而缩写的示例，不替换现有保存模板或用户的完整分析框架。

原型不连接账号、不发送到外部 Agent。点击复制会尝试写入真实剪贴板；模板则使用专门的浏览器存储 key 保存，和旧设计稿的存储空间分开。「恢复初始演示」只清除本原型数据，执行前有确认。浏览器不允许存储时明确说明当前页面内保留。

可以复用现有静态服务；没有服务时，在仓库根目录运行：

    python3 -m http.server 5193 --bind 127.0.0.1 --directory docs/design

然后打开 http://127.0.0.1:5193/prompt-workbench.html。若也需要通过网页阅读 Markdown 链接，改为服务整个 docs 目录，并访问 /design/prompt-workbench.html。

## 实施建议

### 先调整交互，不改资料契约

1. 页面增加 use/edit 模式，拆分模板库、本次表单、结果面板和模板编辑区；继续使用现有 UI 组件。
2. 将 pending 按模板保存与预览生成拆分，避免保存状态意外影响生成入口。
3. 服务状态分为已保存模板、按模板 ID 暂存的编辑草稿、本次生成上下文与预览结果。dirty 只属于编辑草稿；使用模板不受草稿切换保护阻断。
4. 为预览增加 fresh/stale 状态。只有当前上下文的成功结果可复制，错误与来源面板就近显示。
5. 使用现有模板 CRUD、变量目录、命盘和预览接口；生成并复制只是成功预览后的客户端动作，不需要新建「执行 AI」接口。
6. 填写项改名保持 key 不变。删除/替换正文引用需要一致更新并可撤销。现有模板字段与内容逐字保留，不能用演示示例覆盖。

### 再完善来源和诊断

正式接入时补齐服务端来源状态：快照载入中/失败、盘面所有权、版本冲突、具体年份或月份段缺失与重试。沿用当前「计算资料必须完整」的约束；原型只演示客户端输入校验，不能作为数据完整性验证。

模板较多时，搜索和筛选必须覆盖账号下全部分页数据，不能只过滤已加载的一页。首轮可以在列表全部加载完成后本地筛选；数量上来再增加服务端搜索，不必为原型新增接口。

### 验收标准

- 从命盘页进入，使用常用流月模板只需要填写动作并触发一次主操作，不需要经过模板编辑、保存、变量定义。
- 默认界面中模板正文不占据填写空间；桌面常用表单与结果同屏可见。
- 换命盘、范围、输入或模板后，旧结果始终不可复制；异步迟到结果不能复活。
- 三份已有实际框架及自建模板原文、字段类型、选填缺失语义不变。
- 梅花完整资料与八字未接入继续阻断；原始起卦请求独立可用。
- 来源快照与基础盘切换有可见反馈，服务端诊断不会被前端「就绪」状态掩盖。
- 复制失败仍能获得完整文本；模板保存失败仍能恢复草稿。
- 390px 手机没有横向页面溢出，对话框有焦点约束并支持 Esc，按钮可用键盘访问。

## 本次验证

已使用 Orca 浏览器运行页面内 DOM 交互检查，并实际查看桌面与手机截图：

- 桌面 1440 × 1000、手机 390 × 844 与 360 × 800 均未发现页面横向溢出；检查了桌面使用/编辑布局和手机填写布局。
- 通过必填聚焦、非整数阻断、选填「未提供」、HTML 作为纯文本显示、用户输入不递归替换、月份范围越界阻断等检查。
- 通过旧结果保留与复制禁用、换命盘清空输入、异步迟到结果不覆盖当前上下文的检查。
- 通过原始起卦请求生成、完整梅花资料缺失阻断、按模板恢复编辑草稿、使用已保存版本等检查。
- 通过新建草稿不提前写入存储、稳定变量名生成、中文搜索资料、按光标插入、保存返回使用、专用浏览器存储及恢复初始演示等检查。对话框可自动聚焦名称，并实际用 Esc 关闭。
- 页面内 JavaScript 语法检查通过，浏览器控制台未发现错误。
- 直接打开本地 HTML 文件可运行，编辑器切换后从正文开头展示；不依赖静态服务器才能体验。

当前自动化浏览器未允许剪贴板写入。已验证复制等待会超时返回，结果和独立复制入口保留；不宣称实际写入成功。正式站点接入后仍需在目标浏览器人工验收真实复制。
