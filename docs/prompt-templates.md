# 提示词模板、关联资料与本次填写

## 1. 目标与 review 结论

保存自己常用的提示词，从命盘和卦例中显式引用资料，再补充每次不同的动作、现实选项或起卦输入，生成完整文本并复制到外部 Agent。东玄不执行提示词，也不自动发送资料。

三个 SubAgent 以用户的三份实际提示词审查后指出：旧版「固定变量 + 一个 question」不足以使用。详见 [review 发现与处理](review-prompt-scenarios.md)。本文件取代旧版提示词机制。

当前先实现紫微资料供给；梅花具有独立入口与原始资料表单，计算规则/引擎未接入前不生成卦象。八字保留独立来源槽位，不能将紫微库内四柱或时辰取样四柱当作完整八字命盘。

## 2. 模板由三部分组成

| 部分 | 用途 | 例子 |
| --- | --- | --- |
| 正文 `body` | 保留用户指令、步骤和约束，在填写位使用命名变量 | Role、Analysis Framework、Constraints 原文 |
| 自动引用 `data_requirements / bindings` | 显式选择来源、快照和查询范围，声明必须完整的资料 | 本命、当前与下一大限、多个流年、连续月份、命盘称呼 |
| 填写定义 `inputs_schema` | 按模板生成本次填写表单，声明类型、必填及缺失策略 | 动作、现状、A/B/C、权衡维度、问题、两个数字 |

模板保存正文、填写项定义、资料要求和 schema 版本。命盘选择、输入值及展开结果属于本次生成上下文，不随模板保存。不把某人的问题默认带给下一个人。

首版填写类型为 `text / textarea / integer`（HTML 原型使用 `number` 标识并按安全整数校验），后续按实际需要扩充枚举或列表；不是开放执行表达式的表单语言。变量名唯一且有限制，输入数量及长度有上限。

```json
{
  "key": "action",
  "label": "近期拟定动作",
  "type": "textarea",
  "required": true,
  "missingPolicy": "block"
}
```

正文引用 `{{input.action}}`。可选项采用 `missingPolicy: marker`，未填时输出“未提供”，保留模板的追问约束，不删除章节、不编造内容。原型中 `required: false` 对应 marker。

## 3. 来源与时间基准

### 允许的资料来源

- `profile.*`：所选命盘的称呼和性别。变量名保留；不默认带入备注或私人笔记。
- `ziwei.*`：所选基础快照及相同规则/版本下的运限结果，不被后来编辑的出生资料覆盖。
- `bazi.*`：独立八字快照。当前能力未接入，引用它时明确阻止生成；不能从紫微四柱假定完整八字资料已就绪。
- `meihua.*`：独立卦例结果及原始起卦输入，有明确来源与规则。
- `input.*`：本次填写，不写回命盘。

主术数用于模板归类，不应成为一律禁止跨来源的规则。跨来源必须显式声明并选择绑定，核对所有权；不允许按同名、同生日隐式拼接。称呼和性别取自所选命盘。八字及梅花结果仍报告未接入。更广的混合模板需要相应来源能力后再开放。

虚岁不是命盘上的固定字段。`asOfDate` 明确“当前大限”与年龄的基准；目标流年列表及月份窗口分别指定。跨春节、跨大限时，每段保留自身年龄和运限。未来窗口不能统一套用基准日大限。“今年”等自然语言以模板所声明的基准解释，跨年资料必须保留年份标签。

### 主要变量

| 变量 | 引用内容 |
| --- | --- |
| `chart.title` | 所选命盘或卦例的名称，不得误用另一术数的盘名 |
| `profile.name / profile.gender` | 所选命盘的称呼，以及这张盘上的性别。变量名保留，方便已有模板继续使用 |
| `question` | 旧模板兼容的本次问题，新模板建议声明 `input.question` |
| `ziwei.birth / ziwei.natal` | 出生口径、本命完整文字资料 |
| `ziwei.gender_age` | 基础快照性别、基准日虚岁及明确时间口径 |
| `ziwei.decade_current` | 基准日所在大限的完整映射、四化、流曜与范围 |
| `ziwei.decades` | 基准日当前与下一大限，分别标识范围；不能漏掉下一大限后仍生成 |
| `ziwei.years` | 所选流年年份集合的全部实际状态段 |
| `years.label` | 目标年份列表与年界口径 |
| `ziwei.current` | 指定日完整叠盘，含大限/童限、流年、小限、流月、流日 |
| `ziwei.months / range.label` | 连续阳历月份窗口的完整资料及请求范围 |
| `bazi.chart` | 完整八字命盘来源，当前未接入 |

替换只执行一次，不递归解析用户填写内容中的括号。禁止任意对象路径、脚本、条件、循环、网络请求与 `eval`。未知变量、括号错误和未声明填写项应报错。

## 4. 以用户原文建立三个验收模板

### A. 流月行动排期

保留“大限为体，流年为纲，流月为应期”、三步框架、完整表格要求和“流月零推算”约束，只替换原来的 `[填写] / [粘贴]`。

自动资料：基准日性别/虚岁、本命、当前大限、目标窗口内所有大限/流年/流月资料。手填：`input.action` 必填。支持用户明确需要的 3–6 个月；不要求把动作埋进一个通用问题框。

### B. 大限与多年选项比较

保留“先盘后事”、四步框架、严禁行业脑补及现实信息不足时先完成纯看盘的约束。

自动资料：本命、当前/下一大限、明确的 2026/2027/2028 等目标流年。填写项独立为 `status / option_a / option_b / option_c / criteria`。

原模板允许现实描述不足时先做第 1、2 步，所以这些现实字段可选，空值明确标为未提供，并告知第 3、4 步需要补充。必要盘面、下一大限或某个目标流年缺失仍然必须阻止生成。允许部分现实资料不等于允许部分计算资料。

### C. 梅花完整卦例分析

保留上卦、下卦、动爻、本卦、互卦、变卦及客观分析要求。手填问题、两个数字；卦象从独立计算结果引用，不能由模板替换器猜测。

另外提供清楚命名的“梅花原始起卦请求”模板，只引用已填问题与数字，并明确尚未起卦、需先确认规则。这是单独模板，不把完整分析模板自动降级成缺卦象的文本。

## 5. 连续月份与多流年的完整性

### 连续月份

用户已确认：从指定**阳历月**起连续 N 个月，按实际流月分段。N 不等于农历流月数量；不是每 30 天加一个月。

正式首版建议 1–12 月；HTML 原型开放 2026-10/11/12 起始、连续 1–6 月。请求区间从首月 1 日至末月最后一天，跨年和不同月长均按日历处理。

分段身份包含本命快照、规则/版本、农历年月/闰月以及实际大限、流年、流月、年龄等影响所请求结果的字段。不能只按农历初一拆分；闰月中途变化按 [紫微规则](ziwei-rules.md) 处理。

每段保留请求覆盖范围、完整农历月范围、实际流月和叠盘有效范围、快照引用。同一结果跨阳历月重复出现时只输出一次完整内容，但保留其余日期的准确引用，不丢覆盖。

### 多流年

输入为明确的流年年份列表，标明春节或其他已验证年界。默认下，流年 2026 覆盖 2026-02-17 至 2027-02-05，不等于阳历 2026-01-01 至 12-31。

按日核对 `{decadal, yearly, age}` 的完整身份，变化时拆成多个状态段；排除流月/流日字段以免无意义地每天拆段。每段输出本命/大限/流年十二宫映射、四化、流曜、年龄、范围和取数基准。不能把某年 11 月 15 日的叠盘当作未经验证的全年资料。

### 数据闸门

预览前校验资料结构而非仅字符串非空：十二宫齐全、层级宫位映射 12 项、四化 4 项、流曜 12 宫数组、所选时间范围完整连续、所有要求的大限/年份存在。空流曜数组表示该宫没有流曜；缺字段表示资料失败。

日期越界、出生前、某段失败、下一大限不可得、旧引擎不能重现都应列出原因并阻断。不得静默截短范围、降低层级或混用计算版本。原型逐日核对样例月份的实际状态与脚本文本覆盖；正式实现仍需独立闰月、童限、范围外边界测试。

## 6. 独立梅花入口

正式路径 `/meihua`，原型 `#/meihua`；排盘页可直接切入。入口包含占问、两个数字、规则状态、可选关联的一张命盘、草稿/卦例和关联提示词，不要求生日。

输入模型：`originalQuestion, methodId, rawNumbers, occurredAt?, timezone?, ruleVersion, chartId?`。输入/草稿与结果分离；保存输入不代表已经起卦。数字范围、零值及负数规则应在流派确认后约束；当前原型仅校验输入为整数。

结果变量为 `meihua.upper / lower / primary / mutual / changed / moving_line / body_use / method / time`。规则未确认时，结果区明确待生成，不显示模拟卦名。将来若允许用户录入既有卦例，必须标识 `user_supplied` 与来源，不宣传为系统计算验证。

实施前待确认：两个数字上下卦次序、取值范围、余零处理、动爻取法、是否加入时间、互变卦与体用规则。模板中的“上卦＝环境”等属于解释要求，不自动成为引擎算法。

原占问属于卦例快照。本次追问与原占问不同应提示确认；修改起卦数字或方法必须重新起卦，不能保留旧卦象拼成新提示词。

## 7. UI 与失效规则

使用顺序：选择模板 → 自动引用资料 → 本次填写 → 完整性检查 → 预览复制。编辑器可定义填写项和插入变量，避免维护代码才能增加一个问题字段。

缺项分组显示：自动资料不可用、计算资料不完整、本次必填未填、输入格式不合法。一次列出所有缺项。选填内容用明确标记保留。

换一张命盘时清理旧的本次填写，避免串到另一张盘；从梅花入口进入时只显式带入该次问题和数字。模板、来源、日期、问题和规则改变都使旧预览失效。复制失败保留完整可选文本。

## 8. 数据契约与实施

`prompt_templates` 保存 `id, user_id, system, title, body, inputs_schema, data_requirements, variable_schema_version, revision, created_at, updated_at`，revision 做乐观锁。`bindings` 与 `input_values` 归属生成上下文，模板不保存某次敏感展开内容。

预览请求包含模板 revision 或草稿定义、各来源快照 ID、基准日、月份范围、流年年份集合及本次填写值。每一来源独立验证账号所有权和版本；不能信任浏览器上传的计算结果。预览返回展开文本、完整性清单、来源/模板版本、查询参数、数据指纹、实际覆盖段与诊断。

接口仍采用模板 CRUD、术数变量目录和 `POST /api/v2/prompt-previews`。解析、资料供给、完整性校验与文字替换分离；同一资料只计算一次。复制留在客户端，默认不保存或记录整段展开内容到日志。

原型模板使用浏览器存储 v2，读取旧 v1 时保留自定义模板并补充本轮样例，不覆盖旧正文。本次填写只在页面会话中；正式站点模板使用账号下的数据库。梅花原始草稿在原型中刷新重置。
