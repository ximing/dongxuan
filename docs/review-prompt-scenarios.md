# 三份实际提示词的 SubAgent review

日期：2026-11-23。对象：用户提供的「流月行动排期」「大限与多年选项比较」「梅花两数断事」原文。

三个 SubAgent 分别审查模板输入机制、紫微资料完整性和梅花入口/架构。结论一致：**原方案方向可保留，但原来的单一 question 与固定引用变量不足以覆盖实际场景。必须补齐以下缺口，不能按原方案直接实施。**

## 发现与修订

| 优先级 | 原缺口 | 本轮修订 |
| --- | --- | --- |
| P1 | 所有临时内容挤在一个问题框，无法校验动作、选项、两个数字 | 每模板声明 `inputs_schema`，自动生成填写表单，区分单行、多行、整数、必填/选填 |
| P1 | 第二份模板没有当前/下一大限与多流年资料 | 新增 `ziwei.decade_current / decades / years`，明确 as-of 与流年年份集合 |
| P1 | 3–6 月实际需求被原型的 1–3 月上限挡住 | 原型扩为连续 1–6 个阳历月；正式契约仍建议最多 12 月 |
| P1 | 字符串非空即当成资料完整 | 对十二宫映射、四化、流曜数组以及完整日期覆盖做校验；空数组代表无流曜，缺字段必须失败 |
| P1 | 虚岁/当前大限没有独立明确的时间锚点 | 性别取自盘面快照；虚岁与当前大限绑定基准日，各目标段携带自身流年/大限/年龄 |
| P1 | 梅花只有禁用占位，没有入口 | 新增 `/meihua` 独立页，填写问题、两个数字、可选人物，保存预览草稿，进入关联模板 |
| P1 | 所有模板强制依赖紫微盘，梅花全部禁止生成 | 按实际依赖检查。纯填写的原始起卦请求可复制；需要卦象的完整模板在缺结果时阻止生成 |
| P1 | 禁止所有跨术数引用，无法引用档案/八字 | 改为显式多来源绑定。提供档案来源、八字待接入状态；不把紫微四柱当作完整八字盘 |
| P1 | 所有空值统一阻止，违背第二份的分阶段分析要求 | 计算资料和必填项缺失阻断；选填现实资料输出明确“未提供”，保留用户要求的追问流程 |
| P2 | 样例只剩简化后的通用提示词 | 纳入用户三份原始框架，只替换填写位置；不删改 Role、推演法则、分析步骤与 Constraints |

修订后的机制详见 [提示词与命盘引用](prompt-templates.md)。首轮三个 SubAgent 只读审查；随后对输入机制与紫微完整性进行二次复核，主 Agent 与输入机制 SubAgent 落地修订。没有将尚未实现的生产能力表述为已验收。

## 独立核实的紫微依据

参考技能已增加 `--decades --as-of`。用 `1993-03-01 / 申时 / 男`、基准日 `2026-11-15` 验证，返回当前农历年 2018–2027 与下一农历年 2028–2037 大限完整宫位、四化与流曜。

多流年不能用每年某一天的流月盘冒充全年。默认春节口径下，从本年春节到次年春节前一日，逐日比对完整 `{decadal, yearly, age}`，恒定段才共享结果。Review 独立验证：

| 流年 | 阳历有效区间 | 所在大限 | 虚岁 |
| --- | --- | --- | --- |
| 2026 | 2026-02-17 ～ 2027-02-05 | 丁巳，26–35 | 34 |
| 2027 | 2027-02-06 ～ 2028-01-25 | 丁巳，26–35 | 35 |
| 2028 | 2028-01-26 ～ 2029-02-12 | 丙辰，36–45 | 36 |

原型新增专用年度文字格式，只输出该状态段经验证的本命/大限/流年层级，不夹带取数日流月作为全年资料。

月份样例新增逐日实际状态核对：检查参考文本提供的所有完整段及重复引用是否连续覆盖请求范围，并验证每条文本覆盖段内部状态恒定、重复段只引用此前完整结果，以及每个真实状态都有对应完整输出。未通过则生成器失败，不标记样例可用。

## 梅花仍待确认的实施前条件

独立入口和原始资料模板可以先做。正式起卦前必须确认数字次序、取值范围、余零处理、动爻取法、时间是否参与、互变卦与体用规则。用户模板中“上卦＝外在/环境、下卦＝内在/自己”等属于模板解释要求，不自动写成计算引擎规则。

## 验收基准

- 模板一：完整本命/当前大限/目标流年及 3–6 月资料 + 必填动作，缺任何计算资料不得复制。
- 模板二：本命、当前/下一大限、2026/2027/2028 的全部实际年度段齐全；现实选项未填时明确标记并保留分阶段追问规则。
- 模板三：原始问题、两个数字与真实卦例分开；未起卦不能生成完整卦例分析提示词。独立的原始请求模板只复制已填资料，并明确尚未起卦。
- 自动引用与用户填写分别展示来源，换人物/盘面清理旧临时填写，修改上下文使旧预览失效。

## 二次复核与验证

二次复核额外发现并修复：梅花带入人物被默认紫微人物覆盖、仅引用盘名时没有显示来源选择、档案来源误标为手填，以及字段定义的重复变量名、属性转义与旧临时值残留。当前/下一大限分别核对十二宫映射与四化。坏 schema 存储不自动覆写原数据。

- 三张合成盘的全部样例重新生成通过；月份覆盖增加两条反例核验，能拒绝段内漏拆变化和引用尚未提供的完整段。
- 输入机制 20 余个定向 VM 场景与 JS 语法检查通过。
- 浏览器验证六个月窗口、三个流年、必填动作缺失、可选现实资料缺失、梅花输入带入、完整模板阻断、原始请求展开，以及模板字段定义保存后刷新恢复。
- 桌面 1440px、手机 390px/360px 检查无整页横向溢出，截图见设计目录。

这些结果验证方案与交互原型；生产服务、数据库持久化和梅花起卦算法仍未实施。
